# Portal do Cliente — status visual e decisões de interface

Branch de documentação: `portal-ui-docs`

## Home — estado atual

Referência visual atual: **V15**.

### Direção visual aprovada
- Fundo preto / grafite escuro.
- Verde oficial PD como cor de destaque.
- Tipografia em CAIXA ALTA, moderna e geométrica.
- Caixas retangulares para títulos, frases e ações — uma caixa por bloco de sentido, não uma caixa por palavra.
- Interface contínua, sem cabeçalhos intermediários entre seções.
- Apenas um cabeçalho principal no topo e um único rodapé no final.
- Rolagem vertical normal no desktop e no mobile.
- A primeira dobra deve mostrar imediatamente os acessos principais.
- Logo oficial PD deve ser usada; não gerar/substituir por outra marca.

### Acessos principais da Home
1. ATENDIMENTO
2. ÁREA PARA EMPRESAS
3. SOLICITAR ORÇAMENTO
4. CONSULTORIA
5. LOJA RÁPIDA
6. PARCERIAS

### Faixa de simplicidade
`[ SEM LOGIN ]   [ SEM CPF ]   [ RETORNO PELO WHATSAPP ]`

### Regras da Home
- Não mostrar lista de serviços individuais.
- Não mostrar preços na Home.
- Não mostrar formulários na Home.
- Não mostrar protocolo na Home.
- Não transformar a Home em catálogo.
- Os seis acessos devem ser o foco visual inicial.

## Fluxo futuro de Consultoria
Ao clicar em CONSULTORIA, futuramente deverá existir uma escolha entre atendimento para CLIENTE/PARTICULAR e EMPRESA. Não implementar ainda nesta etapa visual.

## Próxima etapa
Criar e aprovar visualmente a tela **ATENDIMENTO** antes de desenvolver lógica funcional.

### Método de trabalho
1. Definir a tela em texto/wireframe.
2. Transformar em HTML + CSS visual.
3. Renderizar e revisar.
4. Refinar por versões até aprovação.
5. Só depois integrar funcionalidade/backend.

## Observação de GitHub
A `main` não deve ser alterada durante refinamentos visuais. As versões aprovadas e orientações devem ser mantidas em branch de trabalho/preview e integradas tecnicamente pelo Codex quando a fase visual estiver fechada.
